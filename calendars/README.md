# 统一交易日历

`current.json` 指向按 SHA-256 命名的不可变发布文件。Runner、Stock 和 Android
读取相同结构；每轮策略固定一个版本，APP 使用公开、与账号无关的本地缓存。
公开文件仅包含市场安排，不包含持仓、策略源码、凭据或用户资料。

维护频率：每天北京时间08:17唤醒；正常来源全年每周检查，10—12月缺少下一年度
官方解析结果的日历每天检查一次。来源读取失败后24小时自动重试；已覆盖且未到期
的日历在发起来源请求前跳过。每个暂时网络错误最多请求3次，不重试403、412或验证墙。
尚无解析器的来源仅作每周监测，不为无法自动发布的来源增加每日请求。
部署解析器或数据变更时立即进行一次校验；手动入口可即时检查。
来源检查时间和日历内容版本分离，无内容变化不生成新日历版本。

自动解析发布目前支持：沪深年度休市安排（上交所中文与深交所英文逐个工作日
核对）、NYSE/Nasdaq共同公布的年度休市与提前收盘安排、JPX股票年度休市表、
台股中英文官方接口、伦交所完整年度表、德交所年度表、泛欧巴黎市场年度表。
台股自动查询当年和下一年；空数据不代表全年开市。伦交所滚动表中不完整的
首尾年份不被发布为全年覆盖。德股最后交易日和法股半日市在精确时段未确认前
保持局部UNKNOWN，不套用其他产品或交易所的收盘时间。

`sources.json` 的 `capability`、`publishEnabled` 和 `blockReason` 明确区分可自动
发布、局部时段未知、待首次实测及产品范围阻断。未启用来源按周检查，不触发第四
季度每日抓取。来源格式变化、年度不完整或内容冲突均保留现行版本。
`held_preserving_active_calendar` 表示整体保留；`published_with_held_years` 表示
只有独立通过校验的年份发布，其他年份留下候选及影响报告供复核。

股票、期货和CFD日历独立。不得把A股新年度自动复制为国内期货新年度。
日历覆盖不足或产品特殊时段未知时返回UNKNOWN；不能退回相邻自然日。
网络失败不使覆盖内的已核验缓存失效。日历不能证明行情源已收盘更新或账本已入账。

独立监测：公开日历仓每日北京时间08:47检查版本、来源状态、覆盖与维护运行记录；
Runner每日09:17独立读取同一状态。这里只读公共状态，不每日重复抓取全部官方来源。
周检查超过8天、第四季度缺年检查超过48小时才补检；仅公开日历仓使用本仓库的
GITHUB_TOKEN派发自身calendar-sync工作流，不增加跨仓库令牌权限。已有任务时
不重复派发，排队超过30分钟单独提示；补检派发冷却24小时，响应不确定不重试。
来源读取失败、缺少适配器、覆盖不足分别显示于Actions摘要与警告；不发送邮件。
手动勾选 `recovery_drill` 可进行明确标记的补检派发演练。

## 状态、历史影响与回滚

`status.md` / `status.json` 提供17类日历的能力、已知年份、来源状态和未解决原因。
每日监测成功后记录真实Actions运行号及观察日期；连续30个自然日才标记观察完成。
当前年度缺失及下一年覆盖不足按90/30/7天阈值显示，不能把来源读取成功当作覆盖完整。

历史日期新增变化不会直接激活：完整原始候选保存在 `candidates/<SHA>.json`，对应
`.impact.json` 按日期比较休市、未知、时区、开收盘及半日语义，并单列历史变化。
`automaticFutureOnly` 已为17类产品明确启用：只将严格解析结果中今天之后的日期合入活动版，
今天及历史逐日语义必须保持不变。删除未来旧休市或特殊时段但缺少明确新安排时转为UNKNOWN；
未来UNKNOWN只可由明确休市或已核验时段解决，不因年度表漏行推成正常开市。
历史完整候选单独保留，不能阻塞独立验证的未来修正；完整自动影响报告与来源证据保存在
`operations/automatic/`。A50采用有期限的第三方CFD参考安排，不能将其声明为新浪提供方正式时段。
本地可选 `--ledger-dir` 仅提取日期作交叉检查；计数是日历/日期候选，不是已确认
受影响持仓或账本记录数。命令不改账、不重跑策略，也不把私有记录写入公开报告。

只读命令：

```bash
python3 tools/calendar_ops.py status
python3 tools/calendar_ops.py impact --target <候选或历史发布SHA>
python3 tools/calendar_ops.py rollback-plan --target <历史发布SHA> --expected-current <当前SHA> --reason '明确的回滚原因'
```

回滚仅接受已存在且哈希校验通过的不可变发布文件。预览计划绑定当前版本、目标
版本、原因、复核日期和影响哈希；执行还必须提供计划的 `confirmationSha256`：

```bash
python3 tools/calendar_ops.py rollback --target <历史发布SHA> --expected-current <当前SHA> --reason '与预览完全一致的原因' --confirmation <计划确认SHA>
```

回滚只修改活动指针、状态及审计记录，不修改历史发布字节或账本。当前版本改变或
跨日期计划失效时必须重新预览。云端通过“交易日历检查与更新”的高级 `ops_request`
输入JSON运行同一接口：`status`、`impact`、`rollback-plan`、`rollback`。字段仅允许
`operation`、`target`、`expectedCurrent`、`reason`、`confirmation`、`calendarId`、`year`，不接受私有路径
或命令。报告保留为Actions附件；实际发布需通过当前版本并发校验。

已实现候选的人工复核发布：`review-plan` / `publish-reviewed`。必须指定
`calendarId`、`year`、候选摘要 `target`、当前摘要 `expectedCurrent`、原因 `reason`；
执行还要求预览返回的 `confirmation`。计划绑定最新候选、成功来源的URL/内容摘要、
精确日历/年度、当前版本、逐日影响与复核日期。只将复核的一个年度合入当前版本，
避免旧候选覆盖其他市场的新数据；审计记录保存在 `operations/reviews/`。
产品范围受阻、尚未启用的来源或任何历史日期变化都不能通过这个入口激活。

## 自动发现与来源缓存

SGX配置从官网`config/appconfig.json`读取版本号，随后只允许访问公开CMS的指定交易页面，
只接收`api2.sgx.com`上匹配SGX年历命名规则的PDF；只解析当年和下一年完整年历。
港交所沿用官方证券市场目录。国内期货按交易所登记官方目录与年度通知URL形状，成功发现的
通知地址跨检查保留，不允许跟随第三方链接。目录发现不是年历核验，文件仍须通过完整解析。

国内期货每个成功解析的来源自动保存规范化事实、原文摘要、URL、交易所、解析器版本和原检查
时间。缓存文件按SHA-256不可变保存，索引中的检查时间只有真实解析成功时才刷新。网络失败可
自动恢复；错误摘要、错误交易所/来源、超过14天、过年、格式变化或多来源冲突均拒绝。缓存及
复核事实继续参与五所一致性检查，不能单独替代新年度的完整官方安排。

全自动指维护流程无需手动触发：唤醒、发现、下载、校验、未来发布、回读、失败恢复和审计。
它不表示外部来源一定可达或提供方已经公布资料。状态JSON单列`providerBlockedCalendars`，
以及本次缓存、复核、解析年份；A50另列`thirdPartyReferenceCalendars`，参考窗口外及未公布年度
保持UNKNOWN，不把第三方参考声明成新浪提供方保证。
历史修订仍需独立分析和处理，不能借“人工复核”自动改账。

```bash
python3 tools/calendar_ops.py review-plan --target <候选SHA> --expected-current <当前SHA> --calendar-id SA_EQ --year 2027 --reason '核对官方预测说明后将未来待核准日期标记为未知'
python3 tools/calendar_ops.py publish-reviewed --target <候选SHA> --expected-current <当前SHA> --calendar-id SA_EQ --year 2027 --reason '与预览完全一致的原因' --confirmation <计划确认SHA>
```

国内期货按交易所分别保留解析状态和规范化事实证据，单家网络失败不会抹掉其他
来源的核对结果。五家完整年度和夜盘核对未全部通过时，整体日历仍保持旧版本。
`reviewedFallback` 只允许读取按SHA命名的不可变复核记录；记录明确标注官方索引
复核、公告URL、日期区间、夜盘停市日、复核日期及年末失效日，不伪造原始网页
摘要。仅网络失败时可使用；已读到的官方页面格式变化不能被复核兜底掩盖。
状态明确区分 `live_parse` 与 `reviewed_fallback`，混合核对不会刷新“全部来源直读
成功”的时间。新年度须取得全部来源或新增明确年度的复核，禁止自动复制旧年。

A50第三方参考模式由用户明确允许采用非官方资料后启用。行情身份仍是新浪CHA50CFD，
节假日页面临时不可访问时，可恢复最近7天内成功解析的同源缓存；缓存内容和原始来源摘要均保留，
且必须重新通过新浪产品身份和嘉盛合约规格校验。缓存不会刷新原始核验时间或延长已发布窗口，
规格变化、缓存过期、校验失败或页面返回冲突内容时保留原日历并继续每日续查。
不改成SGX合约，也不使用A股、MSCI中国A50或其他经纪商的一般中国股票假日表。
嘉盛合约规格必须明确识别中国A50 CFD及周一至周五的09:00—16:30、17:00—次日05:15；
节假日表必须精确选取“中国A50指数”行，并校验北京时间、滚动日期顺序和当前年份。
月日按“即将到来的节假日”上下文解析到当前/相邻年，规则在数据中明确记录；不是年度全覆盖。

发布窗口从检查日次日起，最远45天且不超过节假日表最后日期。一般工作日依合约周时段作为
参考NORMAL，周末为参考CLOSED；表中明示关闭则CLOSED，部分时段无法完整表达则UNKNOWN。
已发布窗口缩短时，撤回窗口外仍在未来的旧参考结论。源格式/产品/年份不匹配时拒绝更新，
今天及历史记录保持不变，网络失败保留仍有效的已核验参考窗口，过期后不向后延长。
活动记录与状态页均标记`third_party_reference`、参考商、起止日和`providerScheduleVerified=false`。
不能把“新浪身份+嘉盛CFD参考”描述为新浪年历或独立多家日历一致性证明。

例如只读影响报告：`{"operation":"impact","target":"<完整64位SHA>"}`。
空 `ops_request` 继续执行正常来源检查。历史影响与回滚命令没有自动改账入口。

运行：`python3 -m unittest discover -s tests -p 'test_calendar_*.py' -v`；
检查：`python3 tools/calendar_sync.py`；即时检查：增加 `--force`。
